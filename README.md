# Workout Activity Tracker

A simple cross-platform mobile app built with **Ionic Framework (Vue) + Firebase**.
It lets you log workouts and does full **CRUD** (Create, Read, Update, Delete)
against a Firestore database, in real time.

Each workout entry has: **exercise name, exercise type, duration, repetitions,
date, and notes.**

## Why it's built this way (the simple version)

- **One collection, one composable.** All Firestore code lives in
  `src/composables/useWorkouts.ts`. It has exactly four operations —
  `addWorkout`, the live `workouts` list, `updateWorkout`, `deleteWorkout` —
  and every screen just calls those functions. No state management library,
  no extra layers.
- **One list screen, one form.** `src/views/HomePage.vue` shows the list of
  workouts and a `+` button. `src/components/WorkoutFormModal.vue` is reused
  for both **adding** and **editing**: if it receives an existing workout it
  edits it, otherwise it creates a new one.
- **Live updates instead of manual refresh.** The composable uses Firestore's
  `onSnapshot` listener, so the list updates itself the moment data changes —
  no pull-to-refresh logic to write or explain.
- **Swipe to edit or delete.** Each row is an `ion-item-sliding`, Ionic's
  built-in swipe gesture, with a confirmation alert before anything is deleted.

## Project structure

```
src/
  components/
    WorkoutCard.vue        # one row in the list (swipe to edit/delete)
    WorkoutFormModal.vue   # add/edit form, reused for both actions
  composables/
    useWorkouts.ts         # all 4 CRUD operations against Firestore
  types/
    workout.ts             # the Workout shape + exercise type options
  views/
    HomePage.vue           # the only screen: list + FAB + modal
  firebase.ts               # Firebase app + Firestore initialization
  router/index.ts            # single route ("/home")
```

## Setup

### 1. Prerequisites

- [Node.js](https://nodejs.org/) 18+
- A free [Firebase](https://console.firebase.google.com/) project with
  **Firestore Database** enabled (start it in test mode, or use
  `firestore.rules` below).
- (Optional, for building the native app) the [Ionic CLI](https://ionicframework.com/docs/cli):
  `npm install -g @ionic/cli`

### 2. Install dependencies

```bash
npm install
```

### 3. Configure Firebase

Copy `.env.example` to `.env` and fill in the values from your Firebase
project (**Project settings → General → Your apps → SDK setup and
configuration**):

```bash
cp .env.example .env
```

```
VITE_FIREBASE_API_KEY=...
VITE_FIREBASE_AUTH_DOMAIN=...
VITE_FIREBASE_PROJECT_ID=...
VITE_FIREBASE_STORAGE_BUCKET=...
VITE_FIREBASE_MESSAGING_SENDER_ID=...
VITE_FIREBASE_APP_ID=...
```

In the Firebase console, create a Firestore database, then publish the rules
in `firestore.rules` (Firestore Database → Rules) so the app can read/write
the `workouts` collection. These rules are open for learning purposes only —
add Firebase Authentication before shipping this to real users.

### 4. Run it in the browser

```bash
npm run dev
```

Open the printed local URL. You can add, edit, and delete workouts right in
the browser — no phone or emulator needed to try the CRUD flow.

### 5. Run it as a native mobile app (optional)

```bash
npm run build
npx cap add android   # or: npx cap add ios
npx cap sync
npx cap open android  # or: npx cap open ios
```

This opens the project in Android Studio / Xcode, where you can run it on an
emulator or a real device. The `android/` and `ios/` folders are generated by
`cap add` and are not committed to git — regenerate them any time with the
commands above.

## Building the Android APK automatically (GitHub Actions)

`.github/workflows/build-apk.yml` builds a debug `.apk` on every push to
`main` (and this dev branch) and on manual trigger, then uploads it as a
downloadable **workflow artifact** — no local Android Studio needed to get an
installable APK.

To let the workflow build with your real Firebase config, add these as
**repository secrets** (Settings → Secrets and variables → Actions →
New repository secret), using the same values as your `.env`:

```
VITE_FIREBASE_API_KEY
VITE_FIREBASE_AUTH_DOMAIN
VITE_FIREBASE_PROJECT_ID
VITE_FIREBASE_STORAGE_BUCKET
VITE_FIREBASE_MESSAGING_SENDER_ID
VITE_FIREBASE_APP_ID
```

After a run finishes, open the workflow run on the **Actions** tab and
download `WorkoutActivityTracker-APK` from the "Artifacts" section — that
`.apk` can be installed directly on an Android device (enable "install from
unknown sources" first) or an emulator.

## How the CRUD flow works (for explaining/demoing)

1. **Create** — Tap the `+` button → fill the form → `useWorkouts().addWorkout()`
   calls Firestore's `addDoc`.
2. **Read** — `useWorkouts()` opens a live Firestore listener (`onSnapshot`) as
   soon as the page loads, so `workouts` always reflects the database.
3. **Update** — Tap a workout (or swipe → edit icon) → the same form opens
   pre-filled → `updateWorkout()` calls Firestore's `updateDoc`.
4. **Delete** — Swipe a workout → delete icon → confirm in the alert →
   `deleteWorkout()` calls Firestore's `deleteDoc`.

Because reads are live, steps 1, 3, and 4 never need to manually refresh the
list — Firestore pushes the change and Vue re-renders automatically.
